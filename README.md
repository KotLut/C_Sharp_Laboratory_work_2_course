# Описание базы данных и классов

В файле три листа, и на каждый из них есть свой класс. Элементы базы данных — это объекты этих классов, а списки `List<Order>`, `List<Service>` и `List<Performer>` лежат внутри `FreelanceDatabase`.

| Лист Excel | Класс | Поля | Связь |
|---|---|---|---|
| Исполнители | `Performer` | `_id` (код), `_age` (возраст), `_citizenship` (гражданство) | — |
| Услуги | `Service` | `_id` (код), `_name` (название) | — |
| Заказы | `Order` | `_id` (код заказа), `_serviceId` (код услуги), `_performerId` (код исполнителя), `_cost` (стоимость в рублях) | `_serviceId` ссылается на `Service`, `_performerId` — на `Performer` |

В каждом классе поля приватные и называются через нижнее подчёркивание. Порядок внутри класса такой: поля, конструкторы (по умолчанию, с параметрами, копирования), свойства, методы, переопределённый `ToString`. Свойства сделаны полными (с `get` и `set` через поле), пока что не через автосвойства.

`ToString` выводит элемент в одну строку, например:

- `Код: 1445, услуга: 11, исполнитель: 326, стоимость: 1 380 979`
- `Код: 11, название: Python-программист`
- `Код: 1, возраст: 32, гражданство: ЮАР`

Стоимость в `ToString` делим на разряды пробелами. Для этого в `Order` есть статический метод `FormatMoney`, который работает через рекурсию: отрезает последние три цифры (`value % 1000`), а всё остальное (`value / 1000`) отдаёт самому себе. Недостающие нули в группе (например, `005`) добавляет `FormatGroup`. Этот же метод используется для вывода итоговых сумм в запросах.

# Пункт 1. Чтение базы данных из Excel

## Загрузка данных из LR5-var6.xls

Прочитать базу данных из Excel-файла.

### Алгоритм решения

1) Читаем файл через `HSSFWorkbook` из библиотеки `NPOI` (это формат `.xls`). Файл открываем внутри `using (FileStream ...)`, чтобы он гарантированно закрылся, даже если при чтении что-то пойдёт не так.
2) Нужные листы достаём по названию: «Заказы», «Услуги» и «Исполнители». Строка с номером 0 — это заголовок, поэтому данные идут с индекса 1 до `LastRowNum`.
3) Список строится одним LINQ-запросом: `Enumerable.Range(1, LastRowNum).Select(...).ToList()`. Для каждого номера строки вызывается свой метод (`ReadOrder`, `ReadService` или `ReadPerformer`), который превращает ячейки в объект. Числа из ячеек приходят как `double`, поэтому приводим их к `int`. Столбцы читаем в том порядке, как они положены в файл (у заказов это код, код услуги, код исполнителя, стоимость). 
4) Сначала списки собираются в локальные переменные, и только когда все три листа прочитаны, они записываются в поля класса. Так при ошибке на третьем листе база не окажется частично загруженной .
5) Чтение запускается автоматически при старте программы. Ещё есть пункт меню 1, который читает файл заново. Если к этому моменту были несохранённые изменения, программа предупреждает, что они пропадут, и просит ответить 1 (продолжить) или 0 (отмена).
6) Ошибки ловим тремя `catch`: `FileNotFoundException` (файла нет), `IOException` (например, файл занят Excel) и общий `Exception` (всё остальное, например, нет нужного листа). Каждый выводит своё сообщение, а `Load` возвращает `false`. Порядок важен: `FileNotFoundException` — частный случай `IOException`, поэтому он стоит первым.

# Пункт 3. Удаление элементов по ключу

## Использую каскадное удаление

Удалить элемент таблицы по его коду.

### Алгоритм решения

1) Выбираем таблицу через `ChooseTable` и вводим код элемента (число от 1 и выше). Сначала проверяем, есть ли такой код, через `HasOrder`, `HasService` или `HasPerformer` (внутри обычный `Any`). Если такого элемента нет, выводим ошибку и возвращаемся в меню.
2) Удаление сделано каскадным. Если у исполнителя или услуги есть заказы, оставлять их нельзя, потому что они ссылались бы на несуществующий код. Поэтому для услуги и исполнителя заранее считаем количество связанных заказов (`CountOrdersByService` и `CountOrdersByPerformer`, внутри `Count` с условием).
3) Если связанные заказы есть, программа пишет, сколько их будет удалено вместе с элементом, и просит подтверждение (1 — да, 0 — нет). При ответе 0 ничего не удаляется. Для обычного заказа вопроса нет, потому что на него никто не ссылается.
4) Само удаление делает `RemoveAll` с условием. В `RemoveService` и `RemovePerformer` сначала удаляем из заказов всё, что связано с этим кодом, а потом сам элемент. `RemoveOrder` удаляет только один заказ.
5) После любого удаления флаг `IsChanged` становится `true`, чтобы при выходе программа предложила сохранить изменения. В конце сообщаем, что элемент удалён, и сколько заказов удалилось вместе с ним.

# Пункт 4. Добавление элементов

## Новый код присваивается автоматически

Добавить новый элемент в любую из таблиц.

### Алгоритм решения

1) Выбираем таблицу через `ChooseTable`. Код нового элемента пользователь не вводит, его присваивает сама база: берём наибольший существующий код и прибавляем 1. В LINQ это `Select(...).DefaultIfEmpty(0).Max() + 1`. `DefaultIfEmpty(0)` нужен для пустой таблицы, иначе `Max` на пустом списке выдал бы исключение. Тогда новый код будет 1.
2) Для исполнителя вводим возраст (от 18 до 125) и гражданство (строка не должна быть пустой, пробелы по краям обрезаются). Для услуги вводим только название. Перед добавлением `HasServiceName` проверяет, нет ли уже такой услуги, и регистр при этом не учитывается (`ToLower`), так что «дизайнер» после «Дизайнер» уже не добавится.
3) Для заказа сначала печатаем список услуг, чтобы код можно было выбрать из него. Дальше вводим код услуги и код исполнителя. В методах `ReadServiceId` и `ReadPerformerId` ввод повторяется, пока не введут код, который реально есть в базе. Так заказ не сможет сослаться на несуществующую услугу или исполнителя. Потом вводим стоимость (от 1 до 100 000 000).
4) Если после удалений не осталось ни услуг, ни исполнителей, заказ добавить нельзя, и программа говорит об этом сразу (иначе проверка кодов крутилась бы бесконечно).
5) Методы `AddOrder`, `AddService` и `AddPerformer` создают объект через конструктор с параметрами, добавляют его в список через `Add`, ставят `IsChanged = true` и возвращают присвоенный код, чтобы показать его пользователю.

## Запрос 5.1. Заказы дороже заданной суммы

Вывести перечень заказов, стоимость которых больше введённой суммы. Обращение к одной таблице (`Заказы`), результат — перечень.

### Алгоритм решения

1) Вводим сумму в рублях (от 1 до 100 000 000). Метод `GetOrdersMoreThan` оставляет в списке заказов только те, у которых стоимость больше этой суммы (`Where`) и сортирует их по убыванию стоимости (`OrderByDescending`).
2) Заказов может набраться тысячи, поэтому на экран выводятся только первые 20 (самые дорогие), а общее количество найденных показывается отдельной строкой. Вырезаем нужную часть через `GetRange`.
3) Если подходящих заказов нет, программа сообщает, что заказов дороже этой суммы нет.

## Запрос 5.2. Выручка по услуге

Найти общую стоимость всех заказов по выбранной услуге. Обращение к двум таблицам (`Заказы` и `Услуги`), результат — одно значение.

### Алгоритм решения

1) Показываем список услуг, и пользователь вводит код. По коду `GetServiceName` находит название услуги (через `First`).
2) В `GetServiceTotal` соединяем заказы с услугами через `join ... on order.ServiceId equals service.Id`, оставляем только строки, где название услуги совпало, и суммируем стоимости через `Sum`.
3) Сумму считаем в типе `long`, потому что у популярной услуги она получается в сотни миллионов, а для `int` это уже на грани. Каждую стоимость перед суммированием приводим к `long`.
4) Результат выводим через `Order.FormatMoney` с разделением на разряды. Если по услуге заказов нет, получится 0.

## Запрос 5.3б. Лучший исполнитель (запрос из примера)

Найти код исполнителя старше заданного возраста с выбранным гражданством, который заработал больше всего при оказании выбранной услуги. Обращение к трём таблицам, результат — одно значение.

### Алгоритм решения

1) Вводим код услуги, гражданство и возраст (от 0 до 100). Исполнитель должен быть строго старше введённого возраста (`Age > minAge`).
2) В `GetBestPerformerId` те же два `join`, что и в предыдущем запросе, но к условиям добавляется возраст. Подходящие заказы группируем по коду исполнителя (`group order by performer.Id into performerOrders`).
3) Для каждой группы считаем сумму стоимостей (`Sum`, снова с приведением к `long`) и сортируем группы по убыванию этой суммы. Первая группа — это самый заработавший исполнитель, а его код лежит в `Key`. Берём его через `FirstOrDefault()`.
4) Если подходящих исполнителей нет, `FirstOrDefault` вернёт 0. Реальных кодов 0 в базе нет, поэтому программа по нулю понимает, что подходящего исполнителя нет, и пишет об этом. Если у двух исполнителей совпадёт заработок, вернётся тот, чья группа встретилась раньше.

# Пункт 6. Сохранение изменений в Excel

## Запись базы данных в файл

Сохранить изменённую базу данных обратно в Excel-файл.

### Алгоритм решения

1) Метод `Save` создаёт новую книгу `HSSFWorkbook` и добавляет в неё три листа с теми же названиями, что были в исходном файле («Заказы», «Услуги», «Исполнители»). В первой строке каждого листа пишем заголовки столбцов, в том же порядке, как они шли в исходном файле.
2) Строки с данными заполняем тем же приёмом, что и при чтении, без циклов: `Enumerable.Range(0, количество).ToList().ForEach(...)`. Для каждой записи отдельный метод (`WriteOrderRow`, `WriteServiceRow`, `WritePerformerRow`) создаёт ячейки через `CreateCell(...).SetCellValue(...)`.
3) Готовую книгу записываем в тот же файл через `FileStream` с режимом `FileMode.Create` (файл перезаписывается). Ошибки ловим двумя `catch`: `IOException` (чаще всего файл открыт в Excel и заблокирован) и общий `Exception`. При ошибке `Save` возвращает `false` и `IsChanged` остаётся `true`, чтобы изменения не потерялись.
4) Пункт меню 9 вызывает `Save`, но только если изменения есть. Если их нет, программа пишет, что сохранять нечего.
5) При выходе из программы (пункт -1) тоже проверяем `IsChanged`. Если есть несохранённые изменения, спрашиваем, сохранить ли их (1 — да, 0 — нет). Если сохранение не удалось, программа не закрывается, а возвращается в меню, чтобы можно было исправить причину (например, закрыть Excel) и повторить.
6) Кстати, программа работает с копией файла рядом с exe-файлом (`bin\Debug\net10.0`), а исходный `LR5-var6.xls` в папке проекта не меняется.
