# Задание 1

## Задача 1 (вариант 6)

### Заполнение двумерных массивов

Первый массив, размерностью n х m, заполняется данными, вводимыми с клавиатуры, так что
заполнение ведется по столбцам от первых элементов столбца к последним.
Второй массив, размерностью n х n, заполняется четырехзначными случайными числами,
составленными из четных цифр.
Третий массив, размерностью n х n, заполняется для произвольного n так же, как для n=5:
1 4 1 2 1
0 2 3 2 1
0 0 3 2 3
0 0 0 4 1
0 0 0 0 5

### Алгоритм решения

1) Все три массива делаем в одном классе Matrix. В классе одно поле - двумерный массив `_array` - и то приватное. Количество строк и столбцов отдельно не храним, их можно получить из самого массива (свойства Rows и Columns).
2) Заполнение реализовано через конструкторы, по одному на каждый массив: `Matrix(n, m)` - ввод с клавиатуры, `Matrix(n, random)` - случайные числа, `Matrix(n)` - массив по образцу. Ещё есть один закрытый конструктор `Matrix(n, m, empty)`, он просто создаёт пустую матрицу нужного размера (нужен внутри класса для результатов операций и транспонирования).
3) Размер проверяется в методе CheckSize: если он меньше 1, программа пишет об ошибке и ставит 1. В меню размер вводится от 1 до 10.
4) Первый массив (n x m) заполняется с клавиатуры по столбцам: внешний цикл идёт по столбцам, внутренний по строкам. Так мы вводим элементы сверху вниз в каждом столбце. Каждое число проверяется через InputValidator (если ввели не число, просим повторить).
5) Второй массив (n x n) заполняется четырёхзначными числами из чётных цифр. Для этого есть метод GetEvenNumber: цифра тысяч - случайное от 1 до 4, умноженное на 2 (получается 2, 4, 6 или 8, ноль тут нельзя, так как иначе число перестанет быть четырёхзначным). Цифры сотен, десятков и единиц - случайное от 0 до 4, умноженное на 2 (0, 2, 4, 6, 8). Потом число собирается из цифр: тысячи * 1000 + сотни * 100 + десятки * 10 + единицы.
6) Третий массив (n x n) заполняется по образцу. Элементы ниже главной диагонали остаются нулями, заполняем только те, где столбец j не меньше строки i. Если разность `j - i` чётная, пишем номер строки (`i + 1`), если нечётная - пишем `n - j`.
7) Для вывода переопределён метод ToString: сначала находим самое длинное число (метод GetMaxLength), потом каждое число выравниваем по правому краю до этой длины, между числами два пробела, всё это обводится рамкой из символов псевдографики. Так массив выводится в виде таблицы (вцелом имеет графические ограничения).
8) В меню выбираем один из трёх массивов, вводим размер и смотрим результат.

# Задание 2

## Задача 2 (вариант 6) 

### Работа с двумерными массивами

Найдите самый короткий путь между максимальным и минимальным элементами двумерного
массива, если разрешается двигаться вправо, влево вверх, вниз и по диагонали.

### Алгоритм решения

1) Задача решается методом `FindShortestPath` того же класса Matrix. Массив для задачи берём случайный n x n (размер от 1 до 10), чтобы сразу было видно и массив, и путь.
2) Сначала один раз проходим по всему массиву и ищем минимальный и максимальный элементы, запоминая их значение и координаты. Если одинаковых значений несколько, берётся первый найденный.
3) Дальше ищем путь поиском в ширину (BFS). Клетки нумеруем одним числом: `номер = строка * количество_столбцов + столбец`, так в очередь можно класть просто числа. Стартуем из клетки с минимумом.
4) Двигаться можно в 8 сторон: вверх, вниз, влево, вправо и по диагоналям. Для этого есть два массива смещений `dRow` и `dCol`, и в цикле мы перебираем все 8 соседей. Сосед подходит, если он не выходит за границы массива и мы в нём ещё не были (массив `visited`).
5) Для каждой клетки, в которую зашли, запоминаем, откуда пришли (массив `prevIndex`, по умолчанию -1). Поиск в ширину идёт слоями: сначала все клетки в один шаг, потом в два и так далее. Поэтому когда мы первый раз дошли до клетки с максимумом - то это кратчайший путь.
6) Чтобы получить сам путь, идём от клетки максимума назад по `prevIndex`, пока не дойдём до -1 (то есть до старта), и разворачиваем список.
7) Если дойти не получилось, метод возвращает «Путь не найден» (в целом массиве такого не бывает, но проверку оставил на всякий случай).
8) Метод возвращает готовую строку: минимум и максимум с координатами (нумерация с 1), длину пути в клетках и сам путь по клеткам со значениями. Строка собирается через StringBuilder.

# Задание 3

## Задача 3 (вариант 6)

### Работа с двумерными массивами как с матрицами

Матричное выражение Aᵀ - (B + Cᵀ)

### Алгоритм решения

1) Выражение считается через перегруженные операторы класса Matrix. Перегружены `+` и `-`, а транспонирование сделано методом `Transpose()` (ведь отдельного оператора в C# для него нет).
2) Операторы `+` и `-` сначала проверяют, что размеры матриц одинаковые. Если нет - выбрасывается исключение с понятным текстом. Потом создаётся пустая матрица такого же размера, и каждый её элемент считается как сумма (или разность) соответствующих элементов двух матриц.
3) Метод Transpose создаёт новую матрицу, у которой строки и столбцы поменяны местами (размер Columns x Rows), и копирует элемент `[i, j]` исходной матрицы в позицию `[j, i]` новой. Исходная матрица при этом не меняется.
4) В программе вводим размер n. Матрицы A и B создаются случайными числами (конструктор из задания 1.2), матрица C - по образцу (конструктор из задания 1.3). Все три матрицы выводятся на экран, чтобы их можно было проверить.
5) Само выражение записано в программе так же, как в условии: `A.Transpose() - (B + C.Transpose())`. Скобки работают как обычно, сначала считается `B + Cᵀ`, потом разность.
6) Результат выводится в виде таблицы через ToString.
7) Для проверки матрицы A, B, C со скриншота были введены в онлайн-калькулятор матриц, и результат получился такой же.

### Бинарные файлы

Переписать в другой файл последовательного доступа те элементы, которые кратны k.

### Алгоритм решения

1) Задания 4-8 сделаны в отдельном статическом классе `FileTasks`, отдельно от класса Matrix, как того и требует условие лабораторной.
2) Исходный файл `data.bin` заполняется случайными данными отдельным методом `CreateBinaryFile`: через BinaryWriter записываем нужное количество целых чисел, каждое случайное в диапазоне от min до max.
3) В программе вводятся: количество чисел (1-100), минимум и максимум (от -1000 до 1000, максимум не меньше минимума) и число k. Ноль для k запрещён, так как на ноль делить нельзя.

6) Чтобы результат было видно, есть метод `PrintBinaryFile`: он читает файл и выводит числа по 10 в строке и их общее количество. Выводим и исходный файл, и результат.

# Задание 5

## Задача 5 (вариант 6)

### Бинарные файлы и структуры - ищем самый дорогой конструктор

Файл содержит сведения об игрушках: название игрушки, ее стоимость в рублях и возрастные
границы (например, игрушка может предназначаться для детей от двух до пяти лет). Получить
название игрушек, цена которых не превышает k руб. и которые подходят детям 5 лет.

### Алгоритм решения

1) Игрушка описана структурой `Toy`: название, стоимость в рублях, минимальный и максимальный возраст. У структуры есть конструктор со всеми значениями и переопределённый ToString.
2) Исходный файл `toys.xml` создаётся отдельным методом `CreateToysFile`. Сначала собираем список `List<Toy>` из случайных игрушек: название берём случайное из заготовленного списка (там есть обычные игрушки и несколько конструкторов), стоимость от 100 до 5000, минимальный возраст от 0 до 11, максимальный - минимальный плюс от 1 до 7, не больше 18.
3) Дальше список записывается в файл через XML-сериализацию (`XmlSerializer` для типа `List<Toy>`). Файл получается в формате XML, его можно открыть и прочитать глазами.
4) Метод `FindMostExpensiveConstructor` читает файл обратно через десериализацию и получает список игрушек.
5) Потом идём по списку и смотрим только игрушки, в названии которых есть слово «Конструктор» (регистр не важен, поэтому сюда попадают и «Конструктор Олега», и «Конструктор Магнитный»). Среди них ищем максимальную стоимость: запоминаем самую большую цену и саму игрушку. Для этого есть флаг, нашли ли мы хоть один конструктор.
6) Если конструкторы нашлись, выводим самую дорогую игрушку и её стоимость. Если нет (при небольшом количестве игрушек так бывает), программа пишет, что конструкторов в файле нет.
7) Для проверки метод `PrintToysFile` выводит все игрушки из файла в виде таблицы, ширина столбцов подбирается по самым длинным значениям.
8) В программе вводится только количество игрушек (1-100).

### Текстовые файлы: сумма элементов, равных своему индексу

Найти сумму тех элементов файла, которые равны своему индексу (индексацию элементов
файла в этой задаче начинать с нуля).

### Алгоритм решения

1) Исходный файл `numbers.txt` заполняется отдельным методом `CreateNumbersFile`: через StreamWriter записываем нужное количество случайных целых чисел от min до max, по одному в строке.

3) Метод `FindSumEqualIndex` читает файл по строкам через StreamReader. Есть счётчик индекса, он начинается с нуля (так, как просили в условии) и увеличивается после каждой строки.
4) Каждая строка переводится в число, и если оно равно текущему индексу, то прибавляется к сумме, и мы выводим, что нашли совпадение. Сумма хранится в типе long, чтобы точно не переполнилась.
5) В конце выводим количество найденных элементов и сумму. Если таких элементов нет, программа сообщает об этом.
6) Для проверки метод `PrintNumbersFile` выводит содержимое файла с индексами в виде `[индекс] = число`, так сразу видно, какие элементы должны попасть в сумму.

# Задание 7

## Задача 7 (вариант 6)

### Решить задачу с использованием структуры «текстовый
файл»

Вычислить произведение элементов, которые кратны заданному числу k.

### Алгоритм решения

1) Исходный файл `multi_numbers.txt` заполняется отдельным методом `CreateMultiNumbersFile`. В каждой строке случайное количество чисел (от 2 до 5), числа записываются через пробел и собираются через `StringBuilder`.
2) В программе пользователем вводятся количество строк (1-50), диапазон значений и число k (не равно 0).
3) Метод `FindProductDivisibleByK` читает файл по строкам. Каждую строку разбиваем на части по пробелам и табуляциям (пустые части отбрасываются), и каждую часть переводим в число.
4) Если `число % k == 0`, умножаем на него общее произведение и выводим, что нашли такое число.
5) Произведение хранится в типе BigInteger: если кратных чисел много, результат получается огромным и в int или long (хотя ранее думал, что в него поместится) просто не поместится.
6) В конце выводим количество найденных чисел и их произведение (оно может быть = 0, так как возможно произойдет * 0). А если кратных чисел нет, программа сообщает об этом.
7) Так как ноль кратен любому k, то если в файле встретился ноль, произведение будет равно нулю. Это не ошибка программы, а результат по определению.
8) Метод `PrintMultiNumbersFile` выводит содержимое файла по строкам, количество строк и количество чисел.

# Задание 8

## Задача 8 (вариант 6)

### Текстовый файл

Переписать в другой файл строки, в которых нет русских букв.

### Алгоритм решения

1) Исходный файл `text.txt` заполняется отдельным методом `CreateTextFile`. Есть два заготовленных набора строк: русские и английские. Для каждой строки случайно выбирается, из какого набора её брать (50 на 50), и потом случайная строка из этого набора.
2) В программе вводится только количество строк (1-50).
3) Метод `FilterLinesWithoutRussian` читает файл по строкам через StreamReader и записывает подходящие строки в файл `filtered_text.txt` через StreamWriter. Кодировка везде UTF-8, чтобы русские буквы не сломались.
4) Чтобы понять, есть ли в строке русские буквы, написан отдельный метод `ContainsRussianLetters`. Он идёт по символам строки и проверяет, попадает ли символ в диапазон А-Я или а-я, а также отдельно проверяет Ё и ё (они не входят в эти диапазоны). Как только нашли хотя бы одну русскую букву, возвращаем true.
5) Если русских букв в строке нет, строку переписываем в новый файл и увеличиваем счётчик. Строки с русскими буквами пропускаем. Строки с цифрами и знаками без букв тоже попадут в результат.
6) Метод `PrintTextFile` выводит исходный и итоговый файлы с номерами строк, поэтому можно сравнить, какие строки остались.
