# Задание 1.6 List

## Найти одинаковые элементы в списке

Составить программу, которая проверяет, есть ли в списке L хотя бы два одинаковых элемента.

### Алгоритм решения

1) Список делаем через `List<string>`. В меню вводим от 1 до 25 элементов руками. Если ввели 0, метод `CreateRandomList` сам наберёт от 2 до 8 слов из заготовленного массива (одно и то же слово вполне может выпасть несколько раз).
2) При ручном вводе метод `ReadList` добавляет строки в конец списка через `Add`. Пустую строку валидатор просит ввести ещё раз, а пробелы по краям обрезает.
3) В `HasDuplicates` идём по списку двумя циклами. Берём элемент с индексом `i` и сравниваем его со всеми, кто идёт после него, начиная с `j = i + 1`. Так элемент сам с собой не сравнивается и одну и ту же пару дважды не проверяем.
4) Как только нашли два одинаковых элемента, возвращаем `true` и дальше список уже не смотрим. Если дошли до конца без совпадений, возвращаем `false`. Регистр при сравнении учитывается (например, «Ёлка» и «ёлка» считаются разными).
5) В консоли сначала показываем сам список, потом пишем, есть ли в нём одинаковые элементы.

## Удаляем первое вхождение

Удалить из списка L первое вхождение заданного элемента, если такой есть.

### Алгоритм решения

1) Здесь список уже связный — `LinkedList<string>`. Количество вводим так же, как в первой задаче: 1–25 для ручного ввода, 0 для автозаполнения. Каждый элемент добавляем в хвост через `AddLast`, чтобы порядок ввода сохранился.

# Задание 3.6 HashSet

## Меломаны и их музыкальные предпочтения

Есть перечень музыкальных произведений. Определить для каждого произведения, какие из них
нравятся всем n меломанам, какие — некоторым из меломанов, и какие — никому из меломанов.

### Алгоритм решения

1) Перечень произведений храним в `HashSet<string>`, чтобы одинаковых названий там не было. Если при заполнении попытались добавить название второй раз, `Add` возвращает `false`, и программа просит ввести другое произведение.
2) В меню можно ввести от 1 до 10 произведений и от 1 до 3 меломанов. Для каждого меломана заводим своё множество понравившихся произведений. Программа спрашивает про каждое название из перечня, и если ответили 1, добавляем его в это множество (0 — пропускаем). Все множества складываем в `List<HashSet<string>>`.
3) Если вместо количества произведений ввели 0, программа сама набирает от 3 до 8 разных названий. Для каждого меломана она случайно решает, нравится ему каждое произведение или нет. Количество меломанов всё равно вводим руками.
4) Чтобы узнать, что нравится всем, в `GetLikedByAll` копируем множество первого меломана и пересекаем его с остальными через `IntersectWith`. Так остаются только названия, которые есть у каждого.
5) Дальше отдельно собираем всё, что нравится хотя бы одному человеку (`GetLikedByAnyone` объединяет множества через `UnionWith`). Из этого объединения убираем то, что нравится всем, через `ExceptWith`. Это и есть «нравятся некоторым».
6) Для «не нравятся никому» берём копию общего перечня и убираем всё, что понравилось хотя бы одному. В конце печатаем перечень, выбор каждого меломана и все три результата. Если где-то ничего нет, выводим «пусто».

# Задание 4.6 HashSet

## Про гласные в одном слове

Файл содержит текст на русском языке. Напечатать в алфавитном порядке все гласные буквы,
которые не входят более чем в одно слово.

### Алгоритм решения

1) Текст сначала записываем в `text.txt` через `StreamWriter`. Можно ввести от 1 до 5 строк или нажать 0 для автозаполнения (тогда будет от 2 до 4 строк, по 3–5 случайных слов в каждой).
2) В `FindVowelsInOneWord` читаем весь файл через `StreamReader`, переводим текст в нижний регистр и разбиваем на слова. В разделители входят пробелы, переносы строк и знаки из массива `_separators`. Пустые части отбрасываем.
3) Для каждого слова делаем свой `HashSet<char>` и пересекаем его с набором русских гласных. Так в слове «мама» буква «а» учитывается один раз, потому что нас интересует количество слов, в которых она встретилась.
4) Есть два общих множества: `met` хранит уже встреченные гласные, а `repeated` — гласные, которые попались в нескольких словах. Сначала пересекаем гласные текущего слова с `met` и добавляем совпадения в `repeated`. Только потом добавляем гласные текущего слова в `met`, чтобы слово не сравнивалось само с собой.
5) В конце убираем из `met` всё, что набралось в `repeated`. Оставшиеся буквы печатаем в порядке `аеёиоуыэюя`. Для проверки перед ответом выводим и сам текст из файла.

# Задание 5.6 Dictionary/SortedList

## Олимпиадники

На вход программе сначала подается число участников олимпиады N. В каждой из следующих N
строк находится результат одного из участников олимпиады в следующем формате:
<Фамилия><Имя><класс><баллы>
где <Фамилия>– символьная строка (не более 20 символов),<Имя>– символьная строка (не более
15 символов), <класс>– число от 7 до 11, <баллы>– целое число набранных участником баллов.
<Фамилия> и <Имя>, <Имя> и <класс>, а также <класс> и<баллы> разделены одним пробелом.
Пример входной строки:
Семенов Егор 11 225
Победителем олимпиады становится участник, набравший наибольшее количество баллов, при
условии, что он набрал более 200 баллов. Если такое количество баллов набрали несколько
участников, то все они признаются победителями при выполнении условия, что их доля не
превышает 20% от общего числа участников.
Победителем олимпиады не признается никто, если нет участников, набравших больше 200
баллов, или больше 20% от общего числа участников набрали одинаковый наибольший балл.
Напишите эффективную по времени работы и по используемой памяти программу, которая
будет определять фамилию и имя лучшего участника, не ставшего победителем олимпиады.
Если таких участников несколько, т.е. если следующий за баллом победителей один и тот же
балл набрали несколько человек, или, если победителей нет, а лучших участников несколько (в
этом случае именно они являются искомыми), то выдается только количество искомых
участников. Гарантируется, что искомые участники (участник) имеются.
Программа должна выводить через пробел фамилию и имя искомого участника или их
количество. Пример выходных данных (один искомый участник):
Семенов Егор
Второй вариант выходных данных (несколько искомых участников):
12

### Алгоритм решения

1) Данные пишем через `StreamWriter` в файл `olympiad.txt`. В первой строке количество участников, дальше по строке на человека: фамилия, имя, класс и баллы. В меню можно ввести от 1 до 30 участников или 0, чтобы программа сама создала от 5 до 15 записей.
2) При ручном вводе фамилия и имя вводятся одним словом (до 20 и 15 символов соответственно), класс — от 7 до 11, баллы — от 0 до 400. При автозаполнении имя и фамилия берутся из заготовленных списков, баллы генерируются с шагом 50.
3) В `FindBestNonWinner` читаем файл по строкам. Заводим два словаря: `counts` хранит количество участников на каждый балл, а `names` — фамилию и имя последнего участника с таким результатом. Имя берём из словаря только тогда, когда на нужном балле ровно один человек, так что перезапись тут не мешает.
4) Дальше одним проходом по ключам ищем два самых больших разных балла. При новом максимуме старый максимум сдвигаем на второе место. Если ключ меньше максимума, но выше текущего второго места, обновляем только второе место.
5) Если максимальный балл строго больше 200 и его набрали не больше 20% участников, считаем эту группу победителями и берём второй по величине балл. Долю в коде проверяем через `counts[bestScore] * 5 <= participantsCount` (так можно обойтись без дробей (типа float)). В остальных случаях берём сам максимальный балл.
6) Если нужный балл набрал один участник, выводим его фамилию и имя. Если участников несколько, выводим их количество. Перед ответом печатаем весь файл, чтобы можно было сверить баллы.

# Задание 6.6 Перегрузка операций

## Вычисление корней квадратного уравнения

Вычисление корней квадратного
уравнения. Результат должен быть
массивом величин типа double (в нем от 0
до 2-х элементов, в зависимости от
количества корней).

### Алгоритм решения

1) Квадратное уравнение храним в классе `QuadraticEquation`. Внутри три приватных поля типа `double` — `_a`, `_b`, `_c`. Снаружи к коэффициентам обращаемся через свойства `A`, `B`, `C`.
2) Конструкторов три. Пустой ставит `a = 1`, `b = 0`, `c = 0`. Конструктор с параметрами записывает переданные числа через свойства. Конструктор копирования берёт все три поля из другого уравнения и делает новый объект. В меню для проверки меняем `B` у оригинала и выводим оба уравнения ещё раз (у копии коэффициент остаётся прежним).
3) Для `A` есть отдельная проверка. Если присвоить 0 через свойство, выводим сообщение и ставим 1. То же самое будет в конструкторе с параметрами, так как он тоже пользуется свойством `A`. При обычном вводе с клавиатуры работает ещё `ReadCoefficientA`: если ввели 0, просим повторить ввод.
4) Для вывода переопределён `ToString`. Знаки для `b` и `c` выбираем отдельно, чтобы получилось `- 3x`, а не `+ -3x`. Нулевые коэффициенты при выводе оставляем, как есть.
5) В `GetRoots` сначала считаем дискриминант `D = b² - 4ac`. Если `D < 0`, возвращаем пустой массив. Если `D = 0`, возвращаем один корень `-b / (2a)`. Если `D > 0`, возвращаем два корня: сначала `(-b - √D) / (2a)`, потом `(-b + √D) / (2a)`.
6) `PrintRoots` смотрит на длину массива и выводит количество корней и их значения. Если массив пустой, пишет «Корней нет».

# Задание 7.6 Перегрузка операций

## Перегрузка операторов для квадратного уравнения

Унарные операции:
++ увеличивает коэффициенты уравнения на 1;
-- уменьшает коэффициенты уравнения на 1.
Операции приведения типа:
double (неявная) – результатом является дискриминант уравнения.
bool (явная) – результатом является true, если корни существуют и falseв
противном случае;
Бинарные операции
== QuadraticEquationt1, QuadraticEquationt2 — уравнения равны, если
равны их коэффициенты;
!= QuadraticEquation1, QuadraticEquation2 — уравнения не равны, если не
равны их коэффициенты.

### Алгоритм решения

1) Операторы перегружаем в том же классе `QuadraticEquation`. `++` прибавляет 1 к каждому коэффициенту, а `--` вычитает 1 из каждого. Оба оператора возвращают новое уравнение через конструктор. Кстати, если при этом вышло `a = 0`, сработает та же проверка из задания 6 и подставит 1.
2) Для проверки в меню сначала выполняем `e2 = e1++`. В `e2` попадает старое уравнение, а в `e1` — новое с увеличенными коэффициентами. Потом делаем `--e1` и ещё раз показываем, что стало с коэффициентами.
3) Неявное приведение к `double` возвращает дискриминант. Достаточно присвоить уравнение переменной типа `double`, без записи `(double)`.
4) Явное приведение `(bool)` тоже смотрит на дискриминант и возвращает `true`, если `D >= 0` (в том числе при одном корне). При отрицательном дискриминанте получаем `false`.
5) В `==` сравниваем все три коэффициента. Если хотя бы одна ссылка равна `null`, сравниваем ссылки через `ReferenceEquals`, чтобы не лезть в поля пустого объекта. Оператор `!=` просто возвращает обратный результат `==`.
